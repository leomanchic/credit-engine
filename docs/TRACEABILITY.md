# Прослеживаемость требований

Основание: `credit_engine_spec.docx`, версия 2.0, и отдельное пользовательское задание. Исходный DOCX не изменялся. Номера разделов ниже относятся к ТЗ; `U01` обозначает согласованное значение `candidate.cash_limit` при минимальном DSCR продукта, `A01` — уточнение о покрытии кредитной истории. Дополнительные требования пользовательского задания отмечены отдельно.

Статус «проверено локально» означает выполненную проверку поведения, а не наличие файла. «Требует интеграционной проверки» относится к настоящему сайту и защищённому backend. Эти обязанности нельзя подтвердить локальными JSON-примерами.

## Выполненные проверки

Проверки выполнены на Python 3.12.14 из `.venv`, с `PYTHONPATH=src`:

```powershell
$env:PYTHONPATH = 'src'
.venv/Scripts/python.exe -m pytest tests/test_scenarios.py tests/test_properties.py -q
.venv/Scripts/python.exe -m pytest tests/test_finance.py tests/test_components.py tests/test_policy_edges.py -q
.venv/Scripts/python.exe -m pytest tests/test_models.py tests/test_cli.py tests/test_decision_edges.py tests/test_delivery_edges.py -q
.venv/Scripts/python.exe docs/verify_reference_calculations.py
# Все эталоны раздела 17 совпали с независимым расчётом точностью 60 цифр.
.venv-wheel/Scripts/python.exe -I scripts/verify_installed.py
.venv-wheel/Scripts/python.exe -I -m pytest -o pythonpath= -q
# 303 passed; импорт установленного wheel, без src через PYTHONPATH.
```

Все перечисленные запуски завершились успешно, без пропусков и ожидаемых падений. Итоговый полный прогон подтвердил **303 теста из исходников и те же 303 теста против установленного wheel**. Он включает все **42 варианта fixtures** семейств F01–F17 и F04b, проверки моделей, CLI, схем, точных границ и независимого поиска. Дополнительно все 42 ссылки на политики проверены через `PolicyConfig`, а 37 корректных пар входов — через реальные DTO. Пять остальных пар намеренно содержат структурные ошибки и проверены через публичный `evaluate`.

Wheel `dist/credit_engine-2.0.0-py3-none-any.whl` собран и установлен в отдельное `.venv-wheel` из локального файла с `--no-index --no-deps`. [verify_installed.py](../scripts/verify_installed.py) под `-I` подтвердил импорт из `site-packages`, а не `src`; публичный API для F01/F02/F04/F04b/F09; канонический цикл сериализации; CLI stdout/file; коды 0/1/2/3; экспорт четырёх схем, совпадающих со схемами проекта. Реальный сайт не предоставлен, поэтому его интеграция остаётся непроверенной.

## Покрытие сценариев

F01, F02, F03, F04, F04b, F05, F07, F09, F10 имеют по одному полному набору JSON. F06 содержит отсутствие четырёх месяцев и отдельного налога; F08 — нулевой долг, неизвестный долг, ожидающую историю и подтверждённое отсутствие истории; F11 — сезонность и нерегулярный долг; F12 — оба продукта; F13 — три вида дубликатов и несогласованную revision; F14 — значения ниже/на/выше DSCR 1.30 и 1.50, нулевую ставку, нулевой/отрицательный поток, нулевое/отрицательное сырое взыскание; F15 — повтор, перестановку и новую версию политики; F16 — отрицательный COMPLETE, устаревший UNRESOLVED и дубликат проверки; F17 — невозможность по скору и по платёжной ёмкости.

Значения и причины в expected.json заданы независимо от `evaluate`; полный фактический результат не используется как эталон для самого себя. Политики с нулевой ставкой и изменённой версией хранятся отдельно и прямо указаны в `policy_ref.json`.
